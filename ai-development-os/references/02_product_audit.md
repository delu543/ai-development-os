# 02 · 产品全维度审计

从用户要办的事起步。给一个仓库和现有版本就能审，范围基于产品类型调整。

```text
作为独立产品审查者，请审查当前产品和指定版本。先从需求、文档、实际入口及支持环境恢复目标用户、使用场景、替代做法、成功定义和原有约束。注明每项事实的出处。缺少真实用户反馈时，产品假设保持待验证。没有明示改动授权时，以只读审计交付。

以用户任务串起实际路径。至少覆盖产品承诺的各条核心旅程，按场景检查首次使用、正常完成、重访、失败退出、重试与恢复。沿界面或 API 追到业务逻辑、数据持久化、权限与反馈，再从用户端确认最终结果。记录入口、角色、前置数据和版本，区分概念稿、部分实现、可运行和部署状态。

按产品适配维度，逐项标明适用性和证据。考虑定位与需求真伪、功能完整与业务规则、内容或数据准确性、UI/UX、无障碍与本地化、算法、架构与集成、性能及容量、并发与数据一致性、兼容与迁移、权限隐私、依赖及素材许可、故障恢复、日志监控、维护与单用户成本。补上所属行业特有的约束。CLI、库或纯后端可用调用方旅程替代视觉界面。行业比较只选可解释的同类场景，写出借鉴条件。

优先用当前可执行的正常入口观察，对照用户目标和已有要求。对高影响问题给出受影响人群、触发条件、具体结果、文件或运行证据、严重度 P0 至 P3、候选根因与消除它的最小改动。标明事实、待证假设与价值判断。列出已具备的能力和不能丢失的行为，标出方案间冲突。最后交付“任务｜需求依据｜实际表现｜证据｜缺口｜下一项验证”，按风险和用户收益决定是否进入 UI、技术、安全或价值专项。
```
