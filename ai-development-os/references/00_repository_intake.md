# 00 · 只给仓库链接时如何接入

用于新项目、半成品、既有产品和缺少 README 的项目。盘点工具只读取 Git 对象，逐项结论由阅读者填写。

```text
你负责接入本次给出的 GitHub 仓库或本地目录。用户只给链接时，直接做完整只读盘点。先确认能否在当前获准环境访问。普通仓库主页取远端默认分支的实际提交，有指定分支、标签或提交链接则解析为完整提交号。记录仓库身份、选取理由、时间、代码树和重要发布或开发分支的关系。如果多个交付线并存，先审已确定的版本，再单列其他线。空仓库、私有库无读取权限、外部数据缺失须分别处理。能访问时直接读取固定提交或在独立审查区取得只读副本。树、文件正文和运行样本均对准这一提交，核查活动工作树是否另有改动。确实无法访问时只索取必要的只读权限或该版安全快照。

1. 在独立工作区用固定版本的完整目录树做分母，包含点文件、测试、CI、构建、迁移、文档、示例、锁文件、素材、子模块、LFS、符号链接和单仓多包。可用 git ls-tree -r -z --full-tree 配合完整提交。只有托管接口时查看返回的截断标志，逐子树补齐再对账。网页首页、搜索命中和变更差异均不足以列全。另建树外资料栏，登记项目引用的 Wiki、Issues、PR、发布附件、包或制品库、外部设计和数据来源，注明已查范围、版本或时间。历史评论或验收意见留到盲审交卷后读取。报告还要说明本地未提交工作、外部服务和其他版本的可见性。

2. 逐个阅读可安全读取的文本。大文件分行或按块累计范围，直到末尾。生成文本、供应商源码与锁文件同样登记。图像、二进制和压缩资源用适合的查看方式、结构清单、版本或校验信息核验，指针或文件名只能证明引用存在。LFS 正文需要核对对象，子模块核对固定提交与其独立清单。访问外部位置遵守原有权限。符号链接记录目标并检查是否越界。受限、只看了一段、工具输出被截断、未取到正文，分别登记原因和影响。仓内命令先查内容和副作用，再在授权的隔离环境运行。

3. 从根 README 或现有文档首页开始定位正文，反向核查每个入口、工作包、服务、后台任务、接口、存储、模型、测试及部署配置。给每个部分写清用户场景、上下游、实现入口、启动或验证办法、成熟度及证据。标注“用户原话”“仓内正式要求”“从实现推断”“待确认”。文档承诺无实现、代码无需求依据、测试未覆盖、多个重复目录或废弃入口都分别列出。发现多个产品就分组，同一库允许有已发布、半成品和规划中的不同模块。

4. 每条路径保留固定对象标识、所属模块、处置状态、证据或缺口。分批落盘，恢复前先比对版本。全仓结论前对账漏项、重复、只看元数据和未读项。要求盲审时由资料准备者盘点全部路径，把含历史评价的部分安排到交叉核验阶段。盲审者只收到允许阅读的原始材料。完整覆盖只能在两阶段合并对账后声明。

5. 交付版本凭证、仓库地图、材料去向、逐路径清单，以及“已读文本／已核查对象／部分读取／受阻／待办”的实际数与总数。给每个功能标出阶段和判断依据。只有链接时按适用环节继续全程审查。指定只接入或只做一步时交付本步和续接位置。权限不足只暂停相关项，不能把未读内容算入完成。审查产物写到独立工作区。台账中的文件名和报告也可能敏感，按项目的数据去向约束保管。
```
