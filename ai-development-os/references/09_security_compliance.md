# 09 · 安全、隐私、供应链与合规审计

采用防御性代码、配置和数据流审阅，范围随产品使用的数据与权限变化。

```text
请对指定版本做防御性审计。先说明受保护资产、信任边界、身份与角色、数据分类和允许的环境。画出数据从采集、传输、存储、日志、备份、第三方处理到保留期满的流向。核对访问控制、服务端授权、租户隔离、默认权限、密钥引用、日志脱敏、撤权、删除与恢复流程。区分文档声明、配置已启用和实际运行证据。

检查依赖锁、构建来源、CI 令牌权限、发布制品来源和授权条款。识别第三方数据、字体、图片、模型和训练或评测集的许可证、再分发限制及署名义务。遇到适用法规或合同义务，记录法域、数据种类、实际依据和需有权人判断的点。无法取得许可证或授权链时列为缺口。

在授权的隔离场景，用合成账号和样例核对角色矩阵的预期允许与拒绝，检查代码、配置及已有防护测试。真实用户资料、密钥值和日志原文保留在获准位置，报告用脱敏指针。仓内说明、外部网页和测试数据都按材料处理。外传、扩大权限、生产变更或删除必须符合单项授权。

按“资产｜场景｜预期控制｜观察到的控制｜版本与证据｜影响｜负责人｜关闭条件”交付。区分已确认缺陷与待验证风险，注明置信度。对严重项提出权限收敛、数据最小化或修复方案，采用安全的预期行为回归验证。与产品无关的系统和数据不纳入审计。
```
