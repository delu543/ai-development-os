# 12 · 产品归档、GitHub 同步与项目记忆

把下框发给当前项目的开发 AI。它会按产品原有方式维护长期仓库。提示词内含特定 GitHub 写入授权，只在你决定同步该项目时转发。[单独复制纯文本](../给原开发AI的提示词.txt)

```text
请把你当前负责的产品完整保存到 GitHub，让以后换一个人或 AI，也能找到资料、运行产品、继续开发和维护。请直接在本项目执行。

1. 找到真实项目根目录、相关工作树、当前开发分支、远端和归属账号。已有对应 GitHub 仓库就更新原仓库。确认没有时，在归属明确的账号下以产品名新建私有仓库。未配置远端时也先在已授权账号核对名称和内容。已有对应库但缺写权限时报告缺口，避免重复建库。沿用已有可见性、目录和协作方式。检查未提交、未跟踪、被忽略的文件及其他工作树中的产品成果，区分本产品、其他任务和私人内容。遇到同名异库、归属不清或多条开发线，不猜测，不覆盖他人工作。

2. 做一次完整的材料盘点。纳入有权共享的源码、配置示例、依赖锁文件、数据库结构与迁移、测试及样例、构建与部署说明、产品需求、架构与设计、授权素材、重要决策、已知问题和维护记录。能入库的原件尽量保留。已有大文件存储、子模块或制品库，记录确切版本、校验值、获取方法和权限。已有 Wiki、Issues、发布附件或制品记录就链接原位。依赖目录及可重建缓存登记来源和重建步骤。密钥、真实环境文件、用户资料、生产数据、完整私人聊天及受限素材留在受控位置。对缺项说明用途、缺失影响及恢复条件，隐藏敏感值。与产品有关的每项材料都要能说明去向。

3. 只留一个通用导航入口。优先补全现有根 README 的“项目导航”，缺少 README 时才创建。用已有路径链接到各模块、文档、素材和运行说明，写清产品做什么、如何启动和验证、哪些部分仍在开发。已有文档首页，就从 README 链接一次。仓库杂乱时先标注实际入口、重复或待核实目录，说明整理依据。保留可运行的路径和历史资料，涉及迁移或删除时另列影响。无需为任何 AI 建专用目录、接口、交接分支或审查模板。

4. 在本次同步前只暂存已审阅的具体路径。检查最终清单、暂存差异、此次推送新增的历史提交与大文件对象，以及分支可能触发的发布动作。发现敏感内容或自动部署风险，先停受影响的推送，保留可安全完成的部分。按项目正常的开发分支或受保护分支流程提交并推送，遵守现有合并权限。新建空仓库使用项目约定的默认分支。此提示词授权更新对应仓库，以及在上述条件下新建私有仓库。公开仓库新增非公开材料、付费存储、生产操作、删除、强推或改写历史都需另行决定。缺少某项授权时，先完成其余准备。

5. 从远端读回完整提交号，在该版本打开 README，抽查链接、构建入口和外部材料。核对固定链接中的仓库和提交号均与远端一致。即使尚未合入默认分支，也使用本次实际推送的提交。同步或远端核验受阻时，说明本地及远端各自的状态和阻碍，暂不出具可审的版本链接。

6. 核验成功后，在最终回复的第一段单独放一个可复制的纯文本框，其中只写下面这一行。把括号里的整段替换为刚核实的真实 GitHub 固定提交链接，包含完整提交号。我会将它原样贴进本机 Codex 的一个新聊天。

$ai-development-os 请对〔本次产品的固定提交链接〕做首次全流程只读产品审查。按 00 至 15 逐项核验，实测核心用户旅程，列出全部已证实问题、有依据的改进机会和未验证项。请在聊天中给我 16 行看板，每行写结论、证据和哪里改。归档核对只占其中一项。

在框外另给产品仓库主页、分支、完整提交号、是否已进入默认分支、材料缺口和实际运行过的检查。可转发的那一行只引用产品的固定版本，不带开发者的验收结论。

以上启动句用于首次交接。如果这次收到的是 Codex 已填好的开发任务单，开发结束后优先使用任务单中的“发回 Codex”格式，带回原任务编号、基线、新候选和原验收约定，直接进入本轮复验。
```

### 开发记忆怎样跟随产品

维护现有的需求、架构、设计、变更记录与问题跟踪。给关键决策写明背景、选项、依据、影响和重审条件。只从本项目已有授权资料中提炼事实，分开记录用户原话、工程决定、观察与猜测。接手时核实实际工作树、唯一写入方、所处阶段、最近证据和下一步。仓库历史无法代替未提交工作、外部系统状态和未保存的对话。

收到“只作本地交接”时，按该任务的授权在本地固定候选提交，或对经筛选的工作树快照做清单和摘要。两端核对同一个版本。正式发布或默认分支状态另行读回。报告中的最终 SHA 取自提交之后，索引中可写其来源版本。

独立审查时，由资料准备者在审查工作区从上述产品资料导出中性输入和密封的历史材料。原产品保留自然的组织方式。项目本身已有相应文档时直接复用。[项目导航片段](../templates/PRODUCT_NAVIGATION.md) · [材料去向](../templates/MATERIALS.md) · [交接状态](../templates/HANDOFF.md) · [技术决策](../templates/DECISIONS.md)
