# 13 · 跨模型接手、盲审与交叉核验

下面两段分两次发。第一段给新会话，第二段在取得独立意见原件后发送。若从产品仓库主页开始，资料准备者在产品仓库以外制作 A、B 两份材料。仓库本身可以照常保留历史信息。

## 第一段，发给独立审查模型

```text
你是本轮独立审查者。输入为允许阅读的 A 包、仓库身份和固定候选版本。A 包仅含原始需求、设计或接口规范、锁定验收条件、指定版本的必要源码、去标识化样本、环境与运行方法。先核验版本和允许读取的路径。自行建立用户旅程、反例、证据和测试，不接收上一模型的结论。

请在隔离的新上下文和工作区审查。资料准备者先筛过 README、AGENTS、CLAUDE、提交说明、文件名和测试报告中可能透露旧结论的内容。遵守适用规则及权限，只给审查者中性的规则说明和必要原件。避免用完整仓库全局搜索、提交日志、PR 讨论、历史验收、决策摘要或旧会话绕过 A 包。必须保留的上级指令已泄露历史判断时，登记受影响范围。若你已看到旧结论，请告知准备者换合适的隔离会话。无法恢复独立性就标为受历史影响的复核。

按原始条件验证，优先用与开发者不同的样例或测量方法，记录覆盖、出现的反例和未知。只提交审查意见，候选代码由指定写入方维护。输出“AC｜独立发现｜输入和操作｜预期与实际｜证据｜结论”。记录模型标识、会话、版本、环境、阅读边界和偏差，无法取得的字段标未知。将结果保存为带时间、内容摘要或 SHA-256 的独立原件，再交给协调者。若不能落盘，可先在单独一条消息交卷，由协调者保留原文和标识。交卷前不要接收 B 包。
```

## 第二段，封存后发给核验者

```text
请执行跨模型交叉核验。输入为同一候选的 A 包识别信息、已经封存的独立意见和 B 包。B 包包含开发上下文、技术决策、已知问题、V1 报告与历史证据。先核对独立意见的原件、时间、版本或摘要。如果独立交卷没有发生，先在新上下文完成该阶段。若无法做到，只交付普通复核并注明原因。

逐项将双方结论映射到 AC、版本、环境、数据和支持证据。分列一致、冲突、单方遗漏和双方都未验证。两种模型意见相同仍要检验客观证据。对冲突设计能区分解释的最小实验，给出复现步骤、预期的不同结果、实际观察和证据。条件不足就保留未决。版本或输入不一致时先标不可直接比较，重新锁定或缩小比较范围。保留首轮原文，把补充结论另行追加。

交付差异矩阵、重大风险、裁决依据及仍待有权人决定的事项。记录是否确为不同模型、是否隔离会话和工作树、哪个版本经哪一方法实测。只有同一模型时标“同模型独立会话”或“自复核”。没有允许向第二服务发送项目资料的授权时，先交付本地中性包和待验证清单。修复由唯一写入方在新候选进行，受影响的核验重新取证。同步、发布和预算均沿用其各自授权。
```
