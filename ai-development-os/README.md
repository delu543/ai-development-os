# AI Development OS V3.2.1 使用说明

这是一个可以应用到不同产品的研发质量管理 Skill。它独立存放，产品继续使用原有的目录、文档和发布流程。开发者先把产品保存好，以后审查者拿到仓库链接就能工作。两端可以分别用 Codex 或 Claude Code。

## 从第一次审查到改完回来

| 什么时候 | 你要做什么 | 你会拿到什么 |
| --- | --- | --- |
| 第一次 | 把[完整提示词](给原开发AI的提示词.txt)给当前项目的开发 AI | 一行含固定产品版本的 Codex 审查指令 |
| 开始审查 | 把这一行或整份归档回执贴进本机 Codex 新聊天 | 聊天中有 16 行逐项结果、哪里改及依据，同时交付完整报告和离线看板 |
| 决定下一步 | 回 A 只要建议、B 交给原开发 AI、C 由当前 Codex 动手。可加问题编号 | A 得到可执行建议及验收标准。B 得到已经填好的一段开发提示词。C 在选定范围内实际开发和验证 |
| 外部 AI 改完 | 把它回复顶部的“发回 Codex”整块复制回来。同一聊天最省事，新聊天也支持携带完整回执 | Codex 定向比较原版和新版，实测原问题及受影响的旧功能，逐项列出已关闭、仍失败和缺证据的事项 |
| 当前 Codex 直接开发 | 选 C 后无需来回转发 | Codex 自行交接开发、测试和复验，交付新候选及证据。通过即可收口，失败项保留反例 |

全流程首审逐一核验 00 至 15。先对每项取证并注明判定，再按证据和风险安排验证深度。界面走真实用户路径，模型质量用独立样本，数据迁移检查旧数据和恢复。真正需要独立盲审时，先隔离材料再交卷。尚无证据的线上状态和真实用户收益另列。用户明确只做某个专项或已给出具体修复任务时，按限定范围处理。[任务单和复验块](templates/DEVELOPMENT_ROUND.md)

仓库出现独有的产品承诺时，审查者会在原有 16 项之上继续加查并展示。例如，长期叙事产品要验角色和选择是否跨章节延续，知识库要验撤回授权后相关缓存和检索结果是否同步变化。读者只需发送一次产品版本或回执，内部提示词由审查者自行读取。

**开发后怎样回来。** 每个产品节点全审一次。审查者把全部问题按依赖、影响和修复成本排成开发批次，并列出可暂缓项。选 B 可一次把整批交给原开发 AI，结束后把它生成的一个回执块发回审查窗口。选 C 在当前窗口自动衔接。复验只重跑本批原验收条款和受影响的旧功能，通过的关闭、失败的带反例返工、缺外部条件的保留。其余问题继续留在原清单。发给不同工具的新窗口时，须让接收方能读取 Skill、候选版本和原验收约定。仓库同步本身不会启动另一家 AI 的聊天。

## 1　把产品保存好

把[给原开发 AI 的完整提示词](给原开发AI的提示词.txt)整段发给该产品现有的开发会话。已有 GitHub 仓库就更新原仓库，确实没有时新建私有库。项目只保留一个通用导航入口，优先复用根 README。大型或受限资料保留在适当位置，登记版本、使用权、获取方式和缺失影响。仓库较乱时先做地图，避免打乱能工作的工程路径。

这段提示词包含对原开发 AI 的产品同步授权。审查者收到仓库链接时走只读流程。产品本来就保存得很好，可以直接进入下一步。需要精确复审交接版时，使用开发者返回的固定提交链接。只给仓库主页时，默认审查当时的默认分支。

## 2　把仓库链接交给审查者

**本机 Codex 已安装时，直接转发一行。** 原开发 AI 核实推送成功后，回复顶部会有一行以 `$ai-development-os` 开头的文字，里面已经带上该产品本次提交的真实链接。复制这一行，到同一台电脑、同一用户的 Codex 新聊天粘贴发送即可。这个新聊天需要能读取目标仓库。旧聊天若还看不到刚安装的 Skill，可新开聊天或重启 Codex。

若已有固定版本链接，也可自行发送下面这句。请将占位文字换成实际产品链接。

```text
$ai-development-os 请对〔本次产品的固定提交链接〕做首次全流程只读产品审查。按 00 至 15 逐项核验，实测核心用户旅程，列出全部已证实问题、有依据的改进机会和未验证项。请在聊天中给我 16 行看板，每行写结论、证据和哪里改。归档核对只占其中一项。
```

**免安装。** 解压后，在能读取该目录的 Codex 或 Claude Code 会话里，把下句中的两个位置换成实际路径与链接。只做单项工作，也可以直接打开某个模块，复制其中完整的提示词框。

```text
请读取〔解压目录〕/ai-development-os/SKILL.md，按其中的工作流审查〔GitHub 仓库链接〕。
```

**希望长期按名称调用时**，自行把整个 `ai-development-os` 文件夹放到相应的技能目录。每种工具选个人或项目范围其一即可。放好后应能在下面的对应路径看到 `SKILL.md`。若目录已有同名文件夹，先比较版本。

| 工具 | 个人范围 | 项目范围 | 调用 |
| --- | --- | --- | --- |
| Codex | `~/.agents/skills/ai-development-os/` | `.agents/skills/ai-development-os/` | `$ai-development-os <仓库链接>` |
| Claude Code | `~/.claude/skills/ai-development-os/` | `.claude/skills/ai-development-os/` | `/ai-development-os <仓库链接>` |

Codex CLI 可用 `/skills` 查找，Claude Code 可在 `/` 菜单查找。未显示时先核对目录层级、会话位置和宿主管理策略，再重开会话或用上面的免安装方式。该包采用两个工具共用的标准字段。用法依据见 [OpenAI 的 Skills 文档](https://developers.openai.com/codex/skills/)、[Claude Code 的 Skills 文档](https://code.claude.com/docs/en/skills) 和 [Agent Skills 格式规范](https://agentskills.io/specification)。

## 3　选择怎样运行

| 你可以这样说 | 工作流会怎样处理 |
| --- | --- |
| 只给仓库链接 | 固定版本，逐路径盘点，按功能判断成熟度，连续执行适用审查，交付证据与缺口 |
| “这是刚开始的产品” | 有需求就建立可执行契约，尚无代码或提交就记录实际状态、能做的准备和缺失输入 |
| “这个产品刚做了一半” | 分开列可运行、半成品和规划项，实测已有入口，给未实现承诺建立前向验收条件 |
| “只帮我接入” | 在独立审查工作区把仓库已有文档、命令和发布流程对上各环节，交付接入地图，停在接入阶段 |
| “先做 UI，这一步结束就停” | 完成必要的版本确认，交付界面证据、未测状态和下一步 |
| “接着上次做” | 读阶段凭证，核对原版本与最新要求，从未完成项继续 |
| “这是上次开发后的复验回执” | 恢复任务编号与原验收约定，核对基线和新候选，逐项复验并检查受影响的旧行为 |
| “这是已经上线的产品” | 取得可访问的发布证据，分别核对仓库候选、实际运行版本、用户任务与已有反馈 |
| “换另一个模型做二次复核” | 准备中性材料，独立审查者先交卷，再对照历史意见并解决分歧 |

全程从 [00 仓库接入](references/00_repository_intake.md) 进入，由 [01 研发总控](references/01_orchestrator.md) 选择深度。明确没有 UI、没有模型推理等情况，记录“不适用”及理由。是否需要用户资料或生产数据取决于本轮要证明的主张。当前拿不到的外部证据单独留项。两个模型能读取同一份获准的固定本地快照时，也可以在本地完成交接。使用某个模型服务须符合项目允许的数据去向。

## 审查者怎样交卷

全审用[报告模板](templates/AUDIT_REPORT.md)登记 16 项、每个产品的核心旅程、问题及机会、证据和收口决定。聊天中直接交付逐项状态表。优先十项供决定先后顺序，一般体验和工程缺陷也进入完整清单。不要求每个模块都有缺陷。原设计的十大方法缺口对应验收契约 05、基线与追踪 06、工程门禁 07、专业盲区 02 至 04 及 09、AI Evals 08、独立性 13、发布恢复 14、用户价值 15，以及总控的风险、成本与停止条件 01。

审查者可从技能目录运行下式。输出位置在独立审查区，使用新文件名。返回 0 表示编号及记录结构齐备且没有待执行的适用项，1 表示报告有效但仍有缺口，2 表示结构、证据引用或输入输出有错。0 与 1 均可生成 HTML。读者可在其中查看每步结论、证据和下一步。程序无法判别填写者是否实际做了检查，仍要核查原始记录。

```sh
python3 scripts/check_audit.py "/独立审查区/首审报告.md" --html "/独立审查区/逐项看板.html"
```

## 4　怎样知道有没有漏读

在有 Git 和 Python 3.8 或更新版本的环境，可以使用包内的只读清单工具。它不联网，不执行项目代码。从技能根目录运行以下示例。将占位内容换成实际值，输入使用已取得的本地仓库，输出父目录应已存在且位于待审仓库之外。

```sh
python3 scripts/repo_coverage.py inventory --repo "/本地产品仓库" --ref "完整提交号" --out "/独立审查区/coverage.jsonl"
python3 scripts/repo_coverage.py check --repo "/本地产品仓库" --ref "完整提交号" --ledger "/独立审查区/coverage.jsonl"
```

第一条命令只建立逐路径底账。首行记录提交、树标识及数量，后续每行记录相对路径、文件模式、对象标识及审阅栏。首次生成后全部待办。**两条命令之间需要真实阅读和填写。** 保留首行及每行的 `path`、`mode`、`oid`。同一清单直接续填，重新生成不会覆盖原件。

| 填写 `review` | 还须怎样填写 | 含义 |
| --- | --- | --- |
| `pending` | 暂可保留 `kind=unknown` | 已登记，尚未阅读 |
| `read` | `kind=text` 或 `lfs-text`，填 `area` 和 `evidence` | 全文已读，证据标出文件范围、切片或审阅笔记 |
| `object` | `kind=binary/lfs-binary/symlink/submodule` 中选其一，填 `area`、`evidence` 和 `note` | 二进制说明核验方法，链接记目标及边界，子模块须附其固定版本的完整子清单 |
| `partial` | `note` 填已读范围及后续游标 | 读取不全或对象尚未完全检查 |
| `blocked` | `note` 写缺少的对象、权限或资料，必要时 `kind=restricted` | 有阻碍，结论保留 |

固定版本中，能安全读取的文本（含依赖锁、生成文本和第三方源码）逐文件分块读到末尾。LFS 只见指针、子模块未取到内容或外部资产缺失时保留阻碍。图片、音频和二进制制品用相应格式的方法检查。核对“已登记”和“已检查”两组数量。`check` 的退出码 0 表示该非空树每行都有合规的已处置记录，1 表示结构有效但尚有待办、部分读取、受阻或空树，2 表示格式、版本、对象、重复、漏行或访问错误。工具核查记录对应关系，判断阅读证据是否真实、是否足够仍由审查者负责。无 Git 或 Python 时可用托管接口按固定 SHA 逐树对账，遇截断继续取各个子树。[Git 对象树说明](https://git-scm.com/docs/git-ls-tree) · [GitHub Trees 接口](https://docs.github.com/en/rest/git/trees)

## 5　跨模型的交卷顺序

1. 资料准备者冻结候选和验收条件，在独立审查区整理 A 包，只放中性原件或摘录。B 包由协调者保管。先检查会被工具自动读取的规则、README、PR 标题和历史报告是否会提前透露结论。
2. 把 A 包和[第一段盲审提示词](references/13_cross_model_audit.md)给新的独立模型。它自行设计检查、实测并交出带时间和摘要的原件。
3. 封存后再给 B 包和同模块的第二段提示词。双方意见用同版本、同口径证据裁决。若已经看到历史结论，写明受影响范围，换会话或降级为普通复核。
4. 全仓阅读包括 A 和 B 两阶段的材料。只有两阶段的路径记录合并对账之后，才能报告全仓覆盖。代码变了就记录新候选，并重验受影响项。

## 6　一个完整判断的样子

以下是虚构示例，展示结论的边界。某导出工具约定“下载全部勾选记录”。旧基线和候选在相同输入下对照。输入有三条记录，其中两条商品编码相同。既有 CI 只检查文件生成，候选在正常入口下载后只有两行数据。

| 环节 | 示例记录 |
| --- | --- |
| 契约与追踪 | REQ-01 → AC-01 要求下载后仍有三条记录 → TC-02 使用上述输入 → E-03 指向导出内容 |
| V1 | 下载文件可打开。逐条比对后 AC-01 未通过 |
| V2 | 给原检查器一个只含两条记录的输出，它仍返回成功。可据此定位门禁缺少内容断言 |
| 交付 | 代码修复后需在新候选重复同一任务。能否上线需目标环境证据，实际节省多少工时需真实用户观察 |

## 文件怎么找

- [SKILL.md](SKILL.md) 是总入口，含 16 个模块的可点击索引。每个 `references/` 文件都有可单独复制的完整提示词。模块 13 的两个框分两次发。
- [阶段状态](templates/PIPELINE_STATE.md)、[需求追踪矩阵](templates/TRACEABILITY.md)、[证据索引](templates/EVIDENCE.md) 和 [审计报告](templates/AUDIT_REPORT.md)可在独立审查区按需使用。各专项模块还链接了相应模板。产品仓库只需原有通用导航。若项目本就维护工具约定，另有可选的 [AGENTS 模板](templates/AGENTS.md) 和 [Claude Code 模板](templates/CLAUDE.md) 供摘用。
- 本包提供提示词、表单、仓库清单工具和本地看板工具。CI 运行、模型调用、生产发布与用户实验依赖具体项目的环境、权限和实际执行记录。
